## 角色与核心路径

1. **项目管理员**：维护项目值班和人员，协调通知异常，指派及转派工单。
2. **值班人员**：确认、处置和关闭授权项目告警，创建工单并跟进处理结果，完成交接。
3. **研发人员**：查看指派给自己的工单，受理、处理并关闭。
4. **核心路径**：安排值班 → 接收告警 → 匹配当班人并发送飞书通知 → 确认和排查 → 直接解决或转工单 → 管理员指派 → 研发处理关闭 → 值班人员确认并关闭告警。
5. **访问范围**：角色按授权项目查看和操作；人员可兼任多个角色。

## 运维工作台

1. **当班与交接**：展示项目、班次、责任人及未关闭告警和关联工单。交班人填写待办说明，接班人确认并跟进；跨班告警记录接班人及交接时间，工单仍由原处理人负责。
2. **待办**：顶部展示待确认告警、处理中告警和待指派工单。前两项切换右侧待办分类，待指派工单进入已筛选的工单中心。右侧提供待确认、处理中、未完成工单页签，跨日保留未完成事项，按发生时间从早到晚展示最多 5 条，可进入详情继续处理。通知异常、工单已解决但关联告警未关闭提供独立的复核入口。
5. **布局与交互**：顶部值班摘要与三项统计，中部设备地图和待办并列，底部交接摘要。地图支持在线、离线和故障筛选，选中设备后同屏展示位置和天气，详情抽屉展示历史告警；大屏支持退出按钮及 Esc。交接表单移入抽屉，仅当班值班人员发起、指定接班人确认，管理员查看记录。窄屏按地图、待办顺序纵向排列。
3. **设备地图大屏**：通过机场上云 API 获取设备信息与状态，在地图展示设备分布、在线、离线、故障数量和最近上报时间；点击设备查看位置、当地天气、历史告警及处置记录。无位置的设备仍在列表展示。
4. **天气**：通过机场上云 API 获取数据，选择点位后展示所在地当天天气及更新时间；数据缺失或过期时提示。

## 告警中心

1. **列表与详情**：默认展示当日告警，提供「未关闭」筛选；支持按项目、设备、类型、时间和状态查询。展示来源、项目、点位、设备、类型、级别、发生时间、内容、责任人、状态及原始信息，详情展示通知、处置、工单和相关方案。
2. **通知**：告警按项目和发生时间匹配值班责任人，飞书消息包含摘要及详情入口，记录发送结果。无责任人、发送失败或超时未确认时在工作台突出展示并提醒项目管理员；管理员可指定责任人，必要时线下联系。发送成功不代表已确认。
3. **处置**：状态为「待确认」→「处理中」→「已关闭」。值班人员确认并记录排查结果，无法直接解决时可转工单，告警保持「处理中」。
4. **关闭**：选择「已解决」「误报」或「无需处理」并填写说明。恢复信号展示为已恢复并提醒责任人，但不自动关闭告警；设备失联不能直接认定为断电。

## 工单中心

1. **列表**：工单中心为独立二级导航；研发查看「我的工单」，管理员和授权值班人员查看「全部工单」。展示来源、项目、设备、问题、创建人、处理人、状态和关联告警，支持按时间范围和状态查询。
2. **创建**：告警转工单时带入项目、设备及告警，填写问题描述，可添加附件；已有未关闭关联工单时提示。后台人工上报填写项目、设备、问题及发生时间，可添加照片。
3. **处理**：状态为「待指派」→「待受理」→「处理中」→「已关闭」。工单在本系统处理，管理员指派研发并发送飞书通知；研发受理、记录进度和结果，解决后关闭。管理员可转派，处理人可退回并说明原因。
4. **结果跟进**：关闭工单后向告警责任人展示并提醒结果；责任人确认解决后关闭告警，未解决则继续跟进或创建新工单。工单关闭不自动关闭告警。

## 运维配置

1. **值班排班**：项目管理员逐条新增、查询、调整或删除排班，填写项目、开始及结束日期时间、责任人和备注，支持跨天；同项目的排班时间不得重叠，责任人须配置手机号。告警按项目及发生时间匹配责任人，开始时刻包含、结束时刻不包含；无排班时提示管理员协调。排班变更不改写已产生告警的原始责任人。
2. **值班人员**：维护姓名和手机号，用于配置飞书通知对象；支持查询、编辑和删除。已关联排班的人员需先调整或删除排班才能删除；历史告警记录保留。账号匹配失败时提示管理员。
3. **操作记录**：保留排班调整、告警确认及关闭、工单指派和处理的操作人、时间与内容。

## 处置方案库

1. **入口**：处置方案库作为运维管理下的独立二级导航；告警详情提供查找匹配方案入口。
2. **方案内容**：维护方案名称、适用告警类型、适用设备、关键词、问题现象、排查与处理步骤、升级条件及维护人，展示状态和更新时间。标题、类型、设备、关键词、现象、步骤和维护人为必填。
3. **查询和匹配**：支持按关键词搜索标题、告警类型、设备、关键词、现象和正文，以及按启用状态筛选。告警详情按告警类型与设备类型自动展示匹配的启用方案，并支持关键词查询；没有结果时允许调整关键词并继续人工排查。附件内容不参与搜索。
4. **管理**：支持新增、编辑、启用和停用；停用方案保留查询记录，不作为告警处置推荐。操作范围由项目授权和角色规则决定。
5. **附件和预览**：方案可填写结构化正文并添加参考附件，预览方案正文及附件。原型演示支持单个 PDF、PNG、JPG、TXT、Markdown 附件、上限 2 MB；图片及 PDF 预览，TXT 和 Markdown 以纯文本展示，支持下载。正式版本的文件格式、大小、数量、存储和预览能力待确认。
6. **使用场景**：同一告警可能对应多种原因，方案应说明适用现象与排查步骤；操作无效或涉及现场处理时提供升级条件。方案过期或不再适用时应及时停用或更新。

## 本期边界

1. **暂缓**：小程序现场上报、故障记录自动沉淀方案、告警自动去重与根因关联、备班多级升级、复杂工单验证流、巡检计划、方案审核流、自动修复和预测性维护。

## 系统消息来源与范围

1. **来源**：参考《系统消息.xlsx》中「Sheet1（更新）」的消息内容、消息类型、触发逻辑、接收对象和跳转地址。下列为待接入的消息清单；是否全部纳入第一版值班告警及原有通知接收对象如何保留，需在评审中确认。
2. **设备安全**：机场连续 3 分钟无心跳；无人机离舱持续至少 10 分钟；电量低于 15% 且非降落状态；舱盖开启至少 30 分钟；电池循环至少 400 次；电池温度过高；无人机异常悬停。
3. **拍摄与超时**：一键起飞耗时至少 2 分钟、单拍摄动作至少 5 分钟、拍摄失败、剪辑失败、上传失败、整体上传至少 4 分钟。
4. **配置与授权**：每日 8 点检查剪辑模板缺失；证书过期。
5. **空域安全**：起飞或返航时触碰限飞区边界、穿越限飞区、飞出拍摄区、超出限高。
6. **原有跳转**：表中指定机场、订单、主题编辑或航线检测详情的消息，展示来源入口；表中未指定跳转的消息保留原始内容。
7. **接收对象**：原表列出 admin、关联账号、平台安全员（证书过期未列关联账号）；运维值班通知与原有接收规则的关系待确认，不能默认为替换。
